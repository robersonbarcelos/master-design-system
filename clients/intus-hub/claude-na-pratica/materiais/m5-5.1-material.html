01

O limite do Claude sozinho

O problema real

Contexto, foco e tempo têm limite.

Um Claude em uma conversa só tem uma janela de contexto, faz uma coisa de cada vez e não consegue paralelizar tarefas. Para projetos longos com múltiplas etapas, isso vira gargalo.

A solução

O Claude chama outros Claudes.

Com agentes, um Claude orquestrador divide o projeto em partes e lança subagentes para cada parte. Cada subagente tem contexto próprio, foco total na sua tarefa e entrega um resultado limpo para o orquestrador montar o resultado final.

03

A analogia que fixa o conceito

Para fixar
Imagine que você tem um clone seu para cada parte do projeto. Cada clone tem contexto próprio e foco total na sua tarefa. Você coordena, eles executam.
Sem agentes

Você sozinho faz tudo.

Pesquisa, analisa e escreve. Cada etapa espera a anterior. 4 horas de trabalho sequencial.

Com agentes

Você passa a missão. Eles entregam.

O orquestrador divide. Cada agente trabalha em paralelo no que sabe fazer. Você recebe o resultado em minutos.

04

Quando usar agentes (e quando é exagero)

Use agentes quando
  • A tarefa tem múltiplas etapas distintas
  • Partes podem rodar em paralelo
  • Envolve múltiplas fontes de dados
  • O projeto é longo demais para um único contexto
Não precisa de agentes quando
  • É uma conversa simples
  • Cria um único arquivo
  • A tarefa resolve em poucos minutos no Chat ou Code
  • Não há paralelismo possível
05

O comando /agents no Claude Code

Para quem quiser explorar

/agents: lista e cria subagentes customizados.

Dentro do Claude Code, o comando /agents mostra os agentes disponíveis e permite criar novos com comportamentos específicos. Este é o ponto de entrada. Configurar agentes avançados é conteúdo do Domínio Claude.
