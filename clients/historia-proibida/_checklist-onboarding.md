# Checklist de Onboarding — Padrão de Referência

> Este arquivo é usado internamente para avaliar qualquer material de cliente recebido.
> Baseado no padrão NovaDAX skill — o mais completo disponível.
> Ao receber material de novo cliente, comparar item a item e reportar o que falta e o que veio a mais.

---

## BLOCO 1 — Identidade e contexto (social-media-context-sms.md)

- [ ] Nome da marca / projeto
- [ ] Segmento / nicho
- [ ] Produto ou serviço principal
- [ ] Proposta de valor (em 1 frase)
- [ ] Público-alvo: perfil demográfico + comportamental
- [ ] Dor principal do público
- [ ] Desejo principal do público
- [ ] Objeção mais comum
- [ ] Nível de consciência do público
- [ ] Plataformas ativas + frequência + objetivo por plataforma
- [ ] Concorrentes diretos (mínimo 2)
- [ ] Como a marca se diferencia
- [ ] Contas de referência de estilo (não copiar)

---

## BLOCO 2 — Marca visual (brand-spec.md)

- [ ] Logo (arquivo SVG/PNG + variações: horizontal, vertical, branco, preto, favicon)
- [ ] Regras de uso do logo (espaço mínimo, tamanho mínimo, fundos permitidos, nunca)
- [ ] Paleta de cores com hex + papel de cada cor (primária, secundária, fundo, texto...)
- [ ] Variáveis CSS prontas
- [ ] Verificação de acessibilidade (contraste AA mínimo)
- [ ] Tipografia: família + pesos + fonte de importação
- [ ] Escala tipográfica (display, h1, h2, body, caption)
- [ ] Assets do produto (screenshots, mockups, fotos reais)
- [ ] Estilo visual geral descrito (atmosfera, referência)

---

## BLOCO 3 — Voz e produção (production-rules.md)

- [ ] Pessoa gramatical (nós / eu / marca em 3ª pessoa)
- [ ] Verbos característicos da voz
- [ ] Tom de voz (mínimo 3 adjetivos)
- [ ] O que a marca NUNCA diz ou parece
- [ ] Padrões de escrita proibidos (específicos, não genéricos)
- [ ] Exemplos antes/depois de reescrita de voz (mínimo 3)
- [ ] Regras de formatação (emojis, travessão, bullets, parágrafos)
- [ ] O que nunca é problema (para não proibir o que é estilo intencional)

---

## BLOCO 4 — Sistema editorial (content-system.md)

- [ ] Editorias definidas (mínimo 3) com objetivo e funil
- [ ] Grade semanal (qual editoria, qual plataforma, qual dia)
- [ ] Estrutura de copy por editoria (hook → corpo → CTA)
- [ ] Tipos de hook por editoria
- [ ] Banco de CTAs aprovados (diretos + interativos)
- [ ] CTAs removidos / fora do tom
- [ ] Banco de dados âncora com regra de rotação semanal
- [ ] Banco de analogias aprovadas (mínimo 3)
- [ ] Hashtags fixas por categoria
- [ ] Modelo de ficha de entrega definido

---

## BLOCO 5 — Sistema visual (visual-system.md)

- [ ] Especificações técnicas por plataforma (dimensões, proporções, formatos)
- [ ] Grupos visuais definidos (mínimo 4) com quando usar cada um
- [ ] JSON padrão para gerador de imagem
- [ ] Negative prompts definidos
- [ ] Regras de prompt (fundo, cor de destaque, tipografia, elementos proibidos)
- [ ] Paleta expandida de iluminação (se aplicável)

---

## BLOCO 6 — Referências (references/)

- [ ] Copies aprovadas (mínimo 3 exemplos reais)
- [ ] Dados âncora confirmados com fonte
- [ ] Banco de temas por editoria (mínimo 5 por editoria)

---

## Como reportar ao usuário

### Se faltar material:
> "Faltou: [lista do que está ausente]. Você tem isso disponível ou quer que eu gere com base no que veio?"

### Se vier material extra não previsto no checklist:
> "Veio isso a mais: [descrição]. Parece interessante — quer adicionar ao modelo padrão?"

### Se o material estiver completo:
> "Material completo. Vou configurar o cliente agora."
